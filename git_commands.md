Роль: Разработчик 1. Создание локального репозитория

git init в папке планируемую как репозиторий
   |
   |
git status проверяет, были ли в репозитории изменения после его создания или последнего коммита (изменения выделены красным цветом)
   |
   |
git add filename/folder/.. добавляет в индекс файл, папку или все содержимое репозитория у которого были изменения после создания репозитория или после последнего коммита
   |
   |
git status (команда опциональна) проверяет, были ли добавлены в индекс изменения (добавленные в индекс изменения выделены зеленым цветом)
   |
   |
git commit -m "краткое описание коммита" фиксирует изменения в индексе

Роль: Разработчик 1. Создание удаленного репозитория GitHub и привязка его к локальному.

Создаем новый репозиторий на GitHub. При необходимости создаем SSH ключи в локальном Bash и экспортируем их на GitHub по инструкции https://github.com/Hexlet/ru-instructions/blob/main/git.md

git remote add origin git@github.com:<username>/<repo name>.git связывает локальный репозиторий с удаленным
   |
   |
git branch -M main переименовывает локальную ветку в main. по умолчанию ветка локального репозитория называется master, что делает невозможным копирование изменений в удаленный реп, т.к. в GitHub локальные ветки по умолчанию называются main
				   Примечание: команда git config --global init.defaultBranch main установит имя будущих локальных репозиториев в main
	|
	|
git push отправляем коммиты в удаленный репозиторий GitHub

Роль: Разработчик 2. Клонирование удаленного репозитория

В CMD преходим в ту папку, где планируется хранить клонированный репозиторий
	|
	|
git clone git@github.com:<username>/<repo name>.git клонирует удаленный репозиторий в локальную папку. Имя папки репозитория будет такая же как и имя удаленного репозитория

Роль: Разработчик 2. Получение новых изменений удаленного репозитория в локальный, при условии, что локальный репозиторий это клон удаленного

git pull --rebase подкачивает новые коммиты удаленного репозитория в локальный

Дополнительные команды для работы с локальным репозиторием:

git rm filename удаляет файл и добавляет изменение в индекс (аналог двух команд git rm + git add)

git restore filename восстанавливает файл в репозитории, при условии если он был удален, но изменения не были добавлены в индекс. После добавления изменений в индекс (git add) восстановить файл уже не получится. Дальше только commit > push

---- Анализ файлов репозитория---------------------------
git diff показывает изменения внесенные в файлы локального репозитория. Только те строки, которые были изменены. Эта команда показывает только изменения, которые еще не добавленные в индекс

git diff --staged тоже самое что и git diff, только показывает изменения уже добавленные в индекс

---- Анализ коммитов репозитория-------------------------
git log показывает список всех коммитов в локальном репозитории отсортированных по дате в обратном порядке

git log -p тоже самое, что и git log, только показывает разницу (git diff) по каждому коммиту в репозитории. Навигация по коммитам может быть объемной, клавиша f - вперед, b - назад, q - выход из навигации

git show <commit ID (hash)> показывает разницу (git diff) по конкретному коммиту. Т.к. хэши имеют большую длину, можно поставить первые 7 символов хэша в качестве ID коммита

git blame <filename> показывает список коммитов по файлу, с информацией кто, когда и в каком коммите его менял
